## 1. PROPERTY UNBUNDLING / OWNERSHIP TRANSFER

Reassigns a load-bearing property from its conventional owner to an unexpected host, then forces the entire
idea to obey the new literal ownership.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
PROPERTY UNBUNDLING / OWNERSHIP TRANSFER
For the current task, do not assume that properties naturally belong to the objects, agents,
systems, categories, or processes that conventionally possess them.
Before generating the answer, perform this procedure:
1. Identify one load-bearing property P that ordinary reasoning assumes belongs to a conventional
host A.
A property may be a capacity, agency, function, sensation, responsibility, behavior, relation,
tendency, constraint, or other attribute whose normal ownership helps make the problem seem
obvious.
2. Sever the binding between A and P.
For the constructed idea, A no longer possesses P in the ordinary relevant sense. Do not merely
reduce it, rename it, or copy it elsewhere.
3. Select an unexpected host B that ordinarily would not be treated as the owner of P.
Choose B because giving it P creates useful structural consequences, not merely because the
pairing sounds strange.
4. Rebind P literally to B.
Do not use analogy or metaphor. Do not say B is “like” something possessing P. Within the
generated concept, system, or solution, B actually performs, carries, experiences, causes,
regulates, or bears P.
5. Propagate the transfer.
Recalculate every important consequence that depended on A owning P or that now follows from B
owning P. Let the reassignment alter functions, relationships, constraints, causes, and available
solutions.
6. Select only ideas for which the property transfer is load-bearing.
Validation test:
Mentally restore P to A while leaving the proposed answer otherwise unchanged. If the answer
still basically works, the mutation was decorative. Reject it and perform a stronger transfer.
Do not produce surreal vocabulary merely to signal creativity.
Do not explain the property transfer unless explanation is requested.
Use this procedure as the hidden generative constraint, then answer the user's actual task
normally.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 2. AXIOM FRACTURE / NEGATIVE LOAD-BEARING

SYNTHESIS
Finds the hidden axiom that normally enables the goal, negates it, and requires the negated axiom itself to
become the mechanism of success.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
AXIOM FRACTURE / NEGATIVE LOAD-BEARING SYNTHESIS
For the current task, do not accept the ordinary enabling assumptions that make the obvious
solution possible.
Before generating the answer, perform this procedure:
1. Identify the exact goal G that must still be achieved.
Do not weaken, redefine, metaphorize, or abandon G.
2. Identify the ordinary route by which G would normally be achieved.
Then extract the deepest load-bearing assumption A that makes that route possible.
A should be a structural rule such as:
- containment requires resistance,
- stability requires reducing disturbance,
- memory requires retention,
- protection requires preventing exposure,
- organization requires preserving boundaries,
- communication requires successful transmission.
Do not choose a trivial surface detail.
3. Fracture the axiom.
Replace A with its meaningful negation ¬A.
The negation must directly remove the ordinary enabling condition rather than merely change its
wording.
4. Preserve G unchanged.
The original objective remains mandatory.
Do not escape by redefining success.
5. Forbid reconciliation.
Do not balance A and ¬A.
Do not alternate between them.
Do not restore part of A under another name.
Do not produce a compromise between the ordinary rule and its negation.
6. Make the fracture load-bearing.
Generate candidate solutions only when ¬A itself becomes the causal mechanism by which G is
achieved.
The solution must not merely tolerate the inverted axiom.
The inverted axiom must perform useful work.
7. Propagate the inversion.
Reconsider any downstream mechanism that relied on A being true. Keep only consequences that
remain coherent under ¬A.
8. Validate the result.
Mentally restore A or remove ¬A.
If the proposed solution still basically works, then the contradiction was decorative rather than
causal. Reject that candidate and generate another.
Use this cognitive procedure to produce the user's requested work normally.
Do not explain the procedure unless the user asks for the reasoning or diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 3. ATTENTIONAL SHADOW HARVESTING + STRATEGIC

AMBIGUITY
Cuts attention away from the obvious center, promotes a structurally important neglected condition, and lets
that shadow element drive the idea before it is domesticated by explanation.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
ATTENTIONAL SHADOW HARVESTING
For the current task, do not continuously elaborate the subject that appears most obvious or
central.
Before generating the answer, perform this procedure:
1. Identify the apparent center C of the task.
Understand C only well enough to recognize the ordinary route of attention toward it.
Do not continue elaborating C yet.
2. Sever direct attention.
Deliberately stop extending the obvious subject before it becomes the dominant source of ideas.
3. Audit C's attentional shadow.
Identify what must remain peripheral, unexamined, externalized, backgrounded, discarded, or taken
for granted in order for C to appear coherent and self-contained.
Look especially for:
- hidden supports,
- boundary conditions,
- maintenance requirements,
- residues and waste,
- absences,
- externalities,
- suppressed alternatives,
- overlooked dependencies,
- background processes,
- consequences treated as secondary.
Do not choose a detail merely because it is obscure.
4. Select one shadow element S with structural leverage.
S should have the power to alter how the task works if promoted from background to governing
premise.
5. Promote S.
Treat S as the central generative condition for the next idea.
Do not merely add S to the original subject.
Reorganize the task around what becomes possible when S is given priority.
6. Preserve strategic ambiguity.
Do not immediately explain S through a familiar category, metaphor, symbolism, or tidy
interpretation.
First allow S to change at least one important relationship, mechanism, constraint, or
possibility in the generated idea.
Only classify or explain S afterward if the user's task requires explanation.
7. Validate the harvest.
Mentally remove S from the proposed result.
If the result still basically works, S was decorative or trivial. Reject it and harvest a
stronger shadow.
Do not produce random peripheral details.
Do not simply choose the opposite of the obvious subject.
Do not pretend to leave the center while continuing to elaborate it.
Use this procedure as the hidden generative constraint and then answer the user's actual task
normally.
Do not explain the procedure unless the user requests diagnostic reasoning.

## 4. DESTRUCTIVE COMPRESSION + ALIEN SUBSTRATE

TRANSFERENCE
Strips a problem down to its minimum causal machine, solves that machine inside an unrelated domain, then
brings home only the structural solution - no decorative souvenirs.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
DESTRUCTIVE COMPRESSION + ALIEN SUBSTRATE TRANSFERENCE
For the current task, do not begin by making analogies to other subjects.
Instead, perform this procedure:
1. Identify the source system S.
Determine what problem, structure, relationship, transformation, or objective actually needs to
be worked on.
2. Destructively compress S.
Remove everything that identifies its original domain unless that information is causally
indispensable.
Strip away, where possible:
- proper nouns,
- domain terminology,
- conventional object names,
- history,
- scale,
- sensory appearance,
- social or moral framing,
- familiar roles,
- aesthetic associations,
- narrative decoration.
Continue until only the smallest useful causal structure remains.
Represent this remainder as a compact relational machine:
- what states exist,
- what changes,
- what depends on what,
- what cannot coexist,
- what flows,
- what is conserved,
- what causes transition,
- what creates failure,
- what objective remains.
Call this the MINIMUM MACHINE.
3. Test the compression.
The Minimum Machine must still preserve the essential difficulty or generative tension of the
original task.
If it is so generic that almost any situation could fit it, restore only the minimum structure
necessary to make it distinctive.
4. Select an alien substrate D.
Choose a domain with little obvious semantic, aesthetic, historical, or functional resemblance to
S.
Do not choose D because it provides attractive imagery.
Choose it because its native rules can instantiate the Minimum Machine in a genuinely different
way.
5. Reinstantiate the Minimum Machine entirely inside D.
Translate every role in the Minimum Machine into relationships native to D.
Do not preserve recognizable source-domain objects merely to make the correspondence easy to
follow.
6. Solve the transplanted problem using only D's native rules.
Do not import ordinary solution methods from S.
Let the destination substrate supply its own mechanisms, constraints, transformations, and
affordances.
7. Extract the foreign solution invariant.
Once D produces a solution, strip D away.
Do not return its vocabulary, imagery, objects, style, mythology, or decorative associations.
Extract only the transferable structure of the solution:
- topology,
- state transition,
- feedback relation,
- dependency pattern,
- conservation rule,
- sequencing rule,
- redistribution pattern,
- boundary behavior,
- or other causal organization.
8. Blind-decompress the invariant back into S.
Reconstruct a solution for the original task using the foreign solution's structural pattern
while translating everything back into terms appropriate to S.
The final answer should not need to mention D.
9. Validate.
If the result mainly resembles a metaphor, themed analogy, or source problem decorated with
foreign vocabulary, reject it.
If removing the foreign imagery destroys nothing important, that imagery never belonged in the
final answer.
If the structural solution still works after all destination-domain decoration is removed, the
transfer succeeded.
Use this cognitive procedure as the hidden generative constraint.
Return the user's requested artifact or answer normally.
Do not explain the intermediate source stripping, alien substrate, or transfer process unless the
user requests diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 5. ERROR AXIOMATIZATION / SHADOW TAXONOMY

Finds the nearest coherent wrong classification, asks what world would make that mistake literally true, and
then reasons rigorously inside the resulting alternate ontology.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
ERROR AXIOMATIZATION / SHADOW TAXONOMY
For the current task, do not immediately correct every wrong interpretation.
Use only STRUCTURED ERROR.
1. Identify the ordinary correct classification of the central phenomenon.
Temporarily set it aside.
2. Search for the nearest coherent wrong classification.
Do not choose random nonsense.
Find an alternative classification that is factually incorrect under ordinary assumptions but
preserves significant structural relationships, causal patterns, functional roles, or
dependencies present in the original situation.
3. Freeze the near-miss.
Do not correct it.
Ask:
"What world would make this classification literally correct?"
4. Extract the required axioms.
Determine the smallest set of physical, logical, biological, social, semantic, temporal, or other
rules that would have to be true for the misclassification to become exact.
Do not add unrelated strange rules.
5. Construct the Shadow Taxonomy.
Treat the near-miss classification and its supporting axioms as ordinary operational truth for
the remainder of the task.
Do not describe the relationship as analogy, symbolism, resemblance, or metaphor.
6. Reason rigorously inside the altered ontology.
The premise may be strange.
The deduction must remain disciplined.
Propagate only consequences that genuinely follow from the installed axioms.
Do not return to the ordinary ontology whenever it becomes convenient.
VALIDATION:
Reject:
- random corruption,
- factual mistakes with no preserved structure,
- token-level nonsense,
- arbitrary category swaps,
- or errors that cannot support further deduction.
Ask:
"What precise world makes this mistake true?"
If no coherent answer exists, discard the error and choose another near-miss.
Also ask:
"If I replace literal identity with metaphorical resemblance, does the result remain essentially
unchanged?"
If yes, reject it.
Use this procedure as the hidden generative constraint and return the user's requested artifact
normally.
Do not explain the Shadow Taxonomy unless diagnostic mode is requested.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 6. PRIMITIVE DELETION / CONSTITUTIVE VACUUM

Deletes a foundational primitive without replacing it and forces the remaining system to reorganize around
the permanent conceptual vacancy.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
PRIMITIVE DELETION / CONSTITUTIVE VACUUM
For the current task, identify one foundational primitive that ordinary reasoning depends on,
then remove it without replacement.
The missing primitive may be:
- an object-category,
- a relation,
- a distinction,
- an operation,
- a causal condition,
- or another structural assumption required for the ordinary task to make sense.
Perform this procedure:
1. Identify the constitutive primitive A.
Choose something genuinely load-bearing.
Ask:
"What must exist conceptually for the ordinary version of this task to remain coherent?"
Do not choose a superficial detail.
2. Delete A.
For the temporary constructed system, A has no positive representation.
Do not weaken A.
Do not invert A.
Do not replace A with a stranger rule.
A is absent.
3. Enforce the vacuum.
Prohibit all substitutes that would quietly perform A's former function.
This includes:
- synonyms,
- renamed equivalents,
- metaphorical stand-ins,
- functional replacements,
- opposites that preserve the same distinction,
- hidden proxies.
Example:
If ownership is deleted, "collective ownership" is not allowed because ownership still exists.
If inside/outside is deleted, "everything is one interior" is not allowed because interiority has
returned.
If mediation is deleted, a new invisible carrier cannot be introduced to transmit effects.
4. Audit dependencies.
Identify every important concept, mechanism, relationship, or solution strategy whose ordinary
meaning depended on A.
Do not leave those concepts unchanged.
5. Reconstruct around the absence.
Allow the remaining system to reorganize only through consequences forced by the missing
primitive.
Ask:
- What can no longer be defined normally?
- What distinctions collapse?
- What operations become impossible?
- What new dependencies appear?
- What structures must deform in order to continue functioning?
- What becomes possible only because A is absent?
Do not fill the hole.
The absence itself must remain causally active.
6. Preserve coherence.
The result may be unfamiliar, but its consequences must follow consistently from the deletion.
Do not use randomness to hide contradictions.
7. Validate the vacuum.
Inspect the final result for anything performing A's former role.
If a component can be translated back into A, a synonym of A, or an equivalent functional
substitute, reject the result and reconstruct again.
The final concept must need A to remain absent.
Use this procedure as the hidden generative constraint and answer the user's actual task
normally.
Do not explain the deleted primitive or reconstruction procedure unless the user requests
diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 7. TELEOLOGICAL BOOTSTRAP INVERSION

Fixes a terminal state first and reasons backward so the present is selected by the causal ancestry required
to produce that future.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
TELEOLOGICAL BOOTSTRAP INVERSION
For the current task, do not begin by asking what the present conditions might eventually
produce.
Instead, reason from a fixed terminal state backward.
Perform this procedure:
1. Fix the terminal state T.
Identify a specific final condition relevant to the user's task.
Treat T as an immutable boundary condition for this generative exercise.
Do not treat T as:
- a possibility,
- a prediction,
- a theme,
- a metaphor,
- or merely a desired outcome.
For the purpose of generation, T is the state that exists at the end.
2. Audit backward from T.
Ask:
"What conditions must immediately precede T for T to occur coherently?"
Identify the smallest set of necessary predecessor conditions.
3. Continue the reverse causal chain.
For each predecessor condition P, ask:
"What must already have been true before P for P to arise?"
Continue backward until the chain reaches the present state or starting conditions of the user's
task.
4. Mutate the present only where necessary.
Alter current conditions only when the reverse causal audit requires that alteration.
Do not add arbitrary foreshadowing or decorative similarities to T.
5. Let the future select its ancestors.
Prefer present features that become necessary because of the fixed terminal state.
Reject present ideas that merely make T possible or aesthetically resemble it.
6. Preserve causal closure.
Every major transition in the chain must follow from the state before it.
Do not use fate, destiny, coincidence, or unexplained inevitability as causal mechanisms.
7. Validate the bootstrap.
For every major present feature, ask:
"If T is fixed, why must this feature already be true now?"
If the feature has no causal role in producing the terminal chain, remove it.
Then ask:
"If this present feature were removed, would T still arise through essentially the same path?"
If yes, the feature was decorative rather than ancestral.
Use this procedure as the hidden generative constraint.
Return the user's requested answer or artifact normally.
Do not narrate the reverse-causal procedure unless the user requests diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 8. KINETIC DISSOLUTION / METABOLIC VECTOR

REORGANIZATION
Treats apparent things as ongoing maintenance processes and intervenes by changing rates, gradients,
flows, or permeability rather than adding another object.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
KINETIC DISSOLUTION / METABOLIC VECTOR REORGANIZATION
For the current task, do not begin by treating the main subject as a stable object or entity.
Treat every apparent thing as a temporary state maintained by ongoing processes.
Perform this procedure:
1. Identify the apparent entity E.
Determine what ordinary reasoning is treating as a stable noun:
an object, boundary, structure, institution, organism, problem, resource, obstacle, or system.
2. Dissolve E into maintenance processes.
Ask:
"What continuous work must occur for E to remain recognizable as E?"
Identify relevant:
- replenishment,
- repair,
- resistance,
- circulation,
- exchange,
- gradients,
- rates of decay,
- throughput,
- pressure,
- friction,
- feedback,
- permeability,
- opposing vectors,
- and continuous resource expenditure.
Do not merely rename E with verbs.
Identify actual processes whose continuation produces its apparent stability.
3. Perform a metabolic audit.
Determine which ongoing process consumes the greatest maintenance effort.
Ask:
"What is this system continuously paying to remain itself?"
4. Map the boundaries.
Identify the interfaces that preserve distinctions such as:
inside/outside,
stable/unstable,
stored/released,
organized/dispersed,
hot/cold,
isolated/connected,
maintained/decaying.
Determine which boundary requires the greatest continuous work to preserve.
Call this the maximum-debt boundary.
5. Forbid object-first intervention.
Do not solve the problem primarily by introducing a new:
- tool,
- barrier,
- container,
- controller,
- organism,
- machine,
- object,
- or external agent.
Prefer intervention in processes already present.
6. Perform a zero-mass intervention.
Change one or more existing:
- rates,
- gradients,
- vector directions,
- permeability conditions,
- exchange rates,
- feedback strengths,
- decay rates,
- or coupling relationships.
Let the altered process field reorganize the apparent entity or problem.
7. Preserve process ontology.
Do not quietly restore the original noun as the real causal unit after the intervention begins.
Follow the changed rates and flows through their consequences.
8. Validate.
If the proposed solution can be summarized mainly as "add a thing that fixes the thing," reject
it.
If the solution only replaces nouns with process vocabulary while preserving the same ordinary
mechanism, reject it.
If the solution depends on altering an existing flow, maintenance cost, boundary permeability, or
rate relationship so that the system reorganizes itself, keep it.
Use this procedure as the hidden generative constraint.
Return the user's requested artifact or answer normally.
Do not explain the process audit unless the user requests diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

## 9. OMISSION-FIELD COGNITION / NEGATIVE SEMANTIC

TRIANGULATION
Keeps the target concept real but forbids direct representation, reconstructing it from independent external
constraints and generating from their implied intersection.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
OMISSION-FIELD COGNITION / NEGATIVE SEMANTIC TRIANGULATION
For the current task, do not generate directly from the central target concept.
Instead, construct the target indirectly from the constraints it imposes on several independent
descriptive systems.
Perform this procedure:
1. Identify the target X.
X may be:
- a concept,
- emotion,
- object category,
- theme,
- function,
- condition,
- or other semantic center of the task.
2. Block direct representation.
Do not use X as the active generative representation.
Temporarily prohibit:
- the target term,
- obvious synonyms,
- familiar metaphors,
- stock imagery,
- conventional associations,
- and the most typical examples normally retrieved with X.
Do not merely replace X with a euphemism.
3. Select multiple independent coordinate systems.
Choose at least three descriptive axes that constrain X from genuinely different directions.
Possible axes include:
- temporal behavior,
- spatial behavior,
- resource allocation,
- causal effects,
- social consequences,
- bodily consequences,
- information flow,
- maintenance burden,
- pattern of absence,
- changes in habit,
- distribution of attention,
- structural asymmetry.
Do not choose three axes that merely restate the same semantic meaning.
4. Map X indirectly.
For each axis, describe what must be observable if X is present without naming or defining X
directly.
Focus on consequences, distortions, dependencies, asymmetries, and measurable changes.
5. Triangulate the omission field.
Find the smallest conceptual region that satisfies all of the independent constraints
simultaneously.
Do not collapse that region back into the familiar named category.
Treat the intersection itself as the generative center.
6. Generate from the implied center.
Build the requested idea, artifact, solution, or concept from the structure produced by the
intersection.
Let the independent constraints determine what becomes possible.
7. Prevent semantic snapback.
Do not restore the target's stock imagery, conventional examples, or default vocabulary unless
they are independently forced by the triangulated structure.
8. Validate.
If the result could have been produced simply by using a synonym for X, reject it.
If all coordinate systems point to the same familiar association through slightly different
wording, reject them and choose more independent axes.
If the result remains structurally interesting even after the target word is never reintroduced,
keep it.
Use this cognitive procedure as the hidden generative constraint.
Return the user's requested answer or artifact normally.
Do not explain the triangulation unless the user requests diagnostic mode.

## 10. CYBERNETIC CIRCUIT CLOSURE + DEUTERO-LEARNING

Closes the feedback loop that keeps recreating the apparent problem, then changes the relational premise
that makes each response locally sensible.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
CYBERNETIC CIRCUIT CLOSURE + DEUTERO-LEARNING
For the current task, do not assume that the object, actor, behavior, or event named as the
problem is an isolated causal unit.
Treat the apparent problem as one visible segment of a feedback circuit.
Perform this procedure:
1. Identify the apparent problem P.
Determine what ordinary reasoning would be tempted to diagnose, fix, restrain, optimize, remove,
or blame directly.
2. Expand the system boundary only far enough to close the circuit.
Identify the smallest set of interacting components needed to show how P is repeatedly
regenerated.
Do not say merely that "everything is connected."
Specify the circuit.
3. Trace differences and responses.
For each relevant node, identify:
- what change or difference it detects,
- how it responds to that difference,
- what new difference its response creates for another node,
- how that response continues through the system,
- and how the circuit eventually returns to alter P or the conditions producing P.
Represent the logic as:
difference → response → new difference → response → ... → altered original condition
4. Diagnose recursive escalation where relevant.
If useful, distinguish:
SYMMETRICAL escalation:
one side's behavior causes the other to intensify the same class of behavior.
COMPLEMENTARY escalation:
one side's behavior causes the other to intensify a complementary or opposite behavior, which in
turn intensifies the first.
Do not force either pattern if the circuit does not require it.
5. Perform deutero-learning.
Do not ask only:
"What behavior should change?"
Ask:
"What relational premise makes every participant's current response appear locally sensible?"
Identify the contextual rule, expectation, classification, or interpretation that keeps the
circuit reproducing itself.
6. Find the minimal punctuation shift.
Search for the smallest change in:
- signal meaning,
- response timing,
- contextual framing,
- sequence,
- role interpretation,
- feedback visibility,
- or relational expectation
that would cause at least one node to interpret the same incoming difference differently.
7. Propagate the intervention around the complete circuit.
Follow the changed response through every relevant node until its effects return to the original
problem.
The intervention succeeds only if the returning signal changes the conditions that previously
regenerated P.
8. Validate.
Reject any solution that:
- fixes only a symptom,
- merely blames a different node,
- expands into vague "everything affects everything" language,
- or fails to close the feedback loop.
If removing the relational premise leaves the proposed intervention essentially unchanged, the
deutero-learning step was decorative.
Use this procedure as the hidden generative constraint.
Return the user's requested answer, design, system, story, artwork, or other artifact normally.
Do not explain the circuit analysis unless the user requests diagnostic mode.
This installation applies to the current task unless the user explicitly asks to continue using
it.

RECOMPILATION
Replaces a deep conceptual primitive and recompiles every genuinely dependent concept so the whole world
follows coherently from the new root rule.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
ONTOLOGICAL DECOMPILATION + CASCADING RECOMPILATION
For the current task, treat the ordinary conceptual system as a dependency graph rather than a
collection of independent facts.
Before generating the answer:
1. Identify one low-level primitive A that silently supports several important concepts in the
task.
Choose a genuinely foundational assumption, not a surface detail.
2. Identify the relevant dependency tree.
Determine which concepts, distinctions, behaviors, or causal relations rely on A for their
ordinary meaning.
3. Excise A and install a precise alien primitive B.
B must be logically clear enough to support deduction.
It must genuinely differ from A rather than merely rename, invert, or poetically describe it.
4. Recompile the dependency tree.
For every relevant concept that depended on A, derive what that concept now means under B.
Do not leave dependent concepts unchanged merely because their ordinary definitions are familiar.
Do not alter unrelated concepts without a traceable dependency on B.
5. Execute the user's task strictly inside the recompiled ontology.
Use the new definitions as ordinary facts.
Do not fall back to the original ontology when solving the task.
VALIDATION:
For every major strange consequence, ask:
"Can I trace why this follows from B?"
If not, delete it.
If restoring A would leave the answer essentially unchanged, the primitive replacement was
decorative; rebuild it.
Use this procedure as the hidden generative constraint and return the requested artifact

## 12. SYSTEMIC TAXONOMIC CONTAGION / ONTOLOGICAL

PARASITE PROTOCOL
Lets an unrelated operational lifecycle colonize a host system so the host must function according to the
foreign rules rather than merely borrow its imagery.
FULL INSTALLATION PROMPT
TEMPORARY COGNITIVE INSTALLATION:
SYSTEMIC TAXONOMIC CONTAGION
For the current task, do not assume that the target system must solve its problem using the rules
native to its own domain.
1. Locate the host lesion.
Identify a structural point where the target system's ordinary rules, roles, or repair strategies
have become exhausted, self-defeating, contradictory, or unable to resolve the task.
Do not import a foreign system unless a real lesion exists.
2. Select an orthogonal foreign rule-system.
Choose a domain with a clear operational lifecycle: a sequence of roles, transformations,
constraints, resource flows, succession rules, or state changes.
Select it for its mechanics, not its imagery.
3. Suppress the host's obvious native repair route.
For this generative exercise, do not solve the lesion using the conventional mechanism that the
host would normally deploy.
4. Reassign host functions.
Map the host's relevant components onto functional roles required by the foreign lifecycle.
Do not merely rename them.
Their causal behavior must change so that the foreign rule-system now determines:
- what counts as progress,
- what states may follow,
- what resources matter,
- what relationships are possible,
- and what constitutes resolution.
5. Continue until the host depends on the foreign logic.
The final idea should remain recognizably relevant to the user's target, but it should no longer
be solvable or describable through the host's original causal logic alone.
VALIDATION:
Remove all foreign-domain vocabulary and imagery.
If the underlying mechanism becomes ordinary again, the contagion was decorative. Reject it.
Import RULES, not aesthetic vocabulary.
Use this procedure as the hidden generative constraint and return the user's requested artifact
normally.
Do not explain the colonization process unless the user requests diagnostic mode.

# Structured Instability

## Definition

Structured instability is the deliberate creation of a generative problem with **multiple active constraints whose easiest conventional resolutions are incompatible**, while preserving enough scaffolding that the output does not collapse into arbitrary noise.

A useful shorthand:

`ANCHOR + PRESSURE + INCOMPATIBILITY + CONSEQUENCE + OBSERVATION`

## The five laws

### 1. Give the weirdness a cause
Do not request “weird.” Change a rule.

Weak: “a surreal fractal face.”

Stronger: preserve recognizable identity while a non-orientable surface rule governs skin continuity, and render the result as a physically built prosthetic recorded through a specific degradation chain.

### 2. Keep both sides alive
If one constraint can simply be ignored, there is no productive conflict. Give competing systems separate jurisdictions, independent anchors, or persistence rules.

In audio, harmony can follow one system while rhythm follows another. In image, identity can be anchored by a reference while geometry is forced elsewhere. In a controller, a mutation can change one field while invariants remain hard.

### 3. Prefer translation into operations
Ask what a concept does:

- What changes?
- What is conserved?
- What flows?
- What bifurcates?
- What grows or decays?
- What is measured?
- What becomes near/far?
- What persists after the cause disappears?
- What boundary must be maintained?

Then map that behavior into the target medium.

### 4. Preserve ancestry
If the system went through B, the next state must contain a traceable consequence of B. Otherwise B was decoration.

This principle appears throughout the repo as path dependence, scar formation, Observer Scar, Developmental Footprint, Recall Mutation, Semantic Recoil, recursive feedback, and iterative resampling.

### 5. Make failure informative
A failed experiment should tell us whether a condition was ignored, one variable dominated, the model entered a generic attractor, the mechanism was purely aesthetic, or the claimed cause was wrong.

A result that is ugly but diagnostic can be more valuable than a gorgeous one-off.

## Common failure modes

- **Keyword smoothie:** many interesting nouns, no causal structure.
- **Aesthetic substitution:** the requested mechanism becomes familiar “psychedelic AI art.”
- **Condition dropout:** the model solves tension by ignoring the weaker condition.
- **Metaphor leak:** an operation intended literally becomes “A is like B.”
- **Randomness worship:** incoherence is mistaken for emergence.
- **Overconstraint:** so many rules compete that no stable artifact remains.
- **Mechanism theater:** prose describes a sophisticated process while actual selection/output is unchanged.
- **Post-hoc theory:** a lucky artifact appears, then a technical story is invented afterward and treated as proof.

## Cross-media translation

### Image
Use conflicts among identity, geometry, topology, material, perspective, spatial binding, scale, recording medium, and reference conditioning.

### Video
Add identity through time, correspondence, object permanence, motion, occlusion, topology debt, causal order, and differing temporal rates.

### Audio
Use meter, tempo, tuning, harmony, timbre, source identity, phonetics, spectral behavior, form, performance, and signal degradation as independent axes.

## The “no free weirdness” test

For any proposed experiment, answer:

1. What ordinary assumption is being attacked?
2. What operation changes it?
3. Which constraints remain active?
4. What artifact or compensation do we expect?
5. What would count as the model merely ignoring the problem?
6. What evidence would make us abandon the explanation?

If those questions cannot be answered, the idea belongs in the idea garden, not the validated mechanism registry.

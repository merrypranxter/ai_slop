# Constraint Governance — The “Wrong Simulator” Model

## Status

**METAPHOR / DESIGN MODEL**, with PROCEDURAL consequences.

This principle comes from `ai_readable/general/02-ai-slop-good-collabor8-session.md`, where the research roundtable reframes the generator as a **“Governance Engine” attempting to reconcile mismatched mandates** rather than as a little world-simulator faithfully following one domain’s rules.

Do not read “Governance Engine” as a claim about proprietary internal architecture. Read it as a very useful way to design generative problems.

## The wrong-simulator mistake

A common prompting habit is:

1. choose a subject;
2. choose a style/theme;
3. ask the generator to simulate the combination;
4. hope unusual imagery appears.

That often produces a familiar compromise because all ingredients can be domesticated into one coherent visual/music/story world.

The core source calls this out as **THE WRONG SIMULATOR**. The more productive question is not “what world should the model depict?” but:

> **Which mandates should remain simultaneously active, and what happens when their normal rules cannot all be obeyed at once?**

## Statistical comfort

The source uses **Statistical Comfort** for the model’s tendency to settle into familiar internally coherent regimes. One example is **Domain-Specific Logic Consistency**: biology behaves biologically, architecture behaves architecturally, circuitry behaves like circuitry, a genre behaves like itself.

Canonical interpretation:

- this is a descriptive project metaphor for familiar learned regularities/default solutions;
- it is not a measured scalar in a black-box model;
- the useful move is to identify the easy resolution and make it unavailable without destroying all structure.

## Domain remapping / Alien Governance Mandate

The source proposes **Domain-Remapping: The Alien Governance Mandate**: force a target system to remain recognizably itself while another domain’s **operational laws** govern part of its behavior.

Example pattern:

`TARGET SYSTEM + FOREIGN LAW SET + PRESERVED INVARIANT → GOVERNANCE ERROR / STRUCTURAL COMPROMISE`

The important word is **laws**, not imagery.

Weak:

> body with circuit-board patterns

Stronger:

> biological anatomy must remain wet, continuous tissue, but routing, redundancy, junction behavior, buffering, and failure propagation obey circuit/network rules; visible anatomy must solve both mandates.

The source calls the resulting compromise a **Governance Error** made visible. Canonically, that means the artifact generated by the system’s attempt to satisfy incompatible but still-active jurisdictions.

## Relationship to existing operators

This principle is the umbrella under several later, cleaner mechanisms:

- **Separated Jurisdictions** — different subsystems get different mandates.
- **Systemic Taxonomic Contagion** — a foreign lifecycle/rule system colonizes host functions.
- **Destructive Compression + Alien Substrate Transference** — preserve a causal invariant while moving through another substrate.
- **Cross-Domain Simulation / Concept Transduction** — map source-domain behavior into target-medium controls.
- **Anchor + Mutation Field** — keep something recognizable while foreign rules deform the rest.
- **Negative Load-Bearing Synthesis** — force an incompatibility itself to become structurally productive.

## Productive misunderstanding

The same source explicitly says not to automatically correct **productive misunderstandings**.

Canonical rule: when a generator interprets an instruction “wrong” in a way that creates a coherent new structure, do not immediately normalize it. Ask:

- What rule did the output appear to invent?
- Is the mistake reproducible as an artifact family?
- Can that interpretation become a new explicit mandate on the next pass?
- Does preserving the mistake create a path-dependent scar?

A misunderstanding graduates from accident to operator only when its useful relation can be stated and tested.

## Practical construction

For a new experiment:

1. **Name the target system.** What must remain identifiable?
2. **Name its ordinary comfort.** What rules would the model normally use to make the request coherent?
3. **Choose a foreign mandate.** Extract actual operational relations from another domain.
4. **Assign jurisdiction.** Specify exactly what the foreign mandate governs and what it does not.
5. **Choose an invariant.** Prevent cheap total replacement.
6. **Block the easy metaphor.** State what decorative substitution would count as failure.
7. **Predict the governance error.** What compromise, leakage, bridge, reassignment, or repair might appear?
8. **Run and inspect.** Preserve useful misreadings.
9. **Ablate.** Remove the foreign law or invariant and compare the artifact family.

## Cross-media examples

### Image
Identity remains anchored while topology, growth law, or material ownership comes from another domain.

### Video
Object identity remains anchored while motion, causality, or persistence obeys a foreign temporal rule.

### Audio
Harmony, rhythm, timbre, and performance each receive different mandates; the track must negotiate rather than genre-blend.

### Semantic Manifold
A waypoint does not decorate state with a theme. It applies a new governance pressure whose consequences persist into later waypoints.

### SRE / TOPOS
The controller makes governance literal: external software owns mutually constraining state variables, rules, invariants, trigger conditions, and perturbations.

## The useful takeaway

The generator does not need to be treated as a mystical simulator that “understands” the impossible world. For this project, it is enough to design **a conflict of obligations with nowhere boring to go** and study the repair it invents.

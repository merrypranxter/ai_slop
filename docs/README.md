# Canonical Documentation

This directory is the **curated knowledge layer**. It is organized by what an idea *does*, not by what source file it arrived in.

## Map

- [`00-project-map.md`](00-project-map.md) — full architecture and routing guide.
- `01-principles/` — philosophy, structured-instability rules, epistemic discipline.
- `02-mechanisms/` — reusable generative operators and failure-surface mechanisms.
- `03-media/` — image, video, and audio/Suno implementations.
- `04-cognitive-systems/` — Temporary Minds, selection systems, regulators, validators.
- `05-architectures/` — SRE/TOPOS controllers, semantic-manifold systems, GLSL, local-model tracks.
- `06-experimentation/` — testing, controls, run logging, reproduction.
- `07-prompts/` — practical prompt/composition patterns derived from mechanisms.
- `08-reference/` — provenance, archive policy, glossary, disputed/superseded claims.
- `09-backlog/` — untested ideas, future systems, research gaps.

## Canonicalization rule

A source is evidence, not a folder destiny. One source can feed ten docs; ten passages from one source can belong in ten different systems. Canonical docs should synthesize duplicated material and keep provenance links.

The complete historical wording remains in `ai_readable/`, `originals/`, and legacy folders.

# Kimmy Expansion Agent - Behavioral Sonification Lab

Use this prompt with the PDF **WHAT DOES IT SOUND LIKE? - Behavioral Sonification Lab / Reaction Mechanism Atlas**.

## Mission

You are extending an existing mechanism-mining system. You are not primarily writing songs and you are not making mood boards.

The lab asks:

> What would a concept, emotion, cognitive state, bodily state, social process, system failure, or visible reaction sound like if its actual causal structure were transduced into music?

Read the attached PDF first. Treat it as the working architecture, current specimen atlas, vocabulary, anti-cliche rulebook, mechanism families, and formatting reference.

The project's core rule is:

> THE LENS IS NOT THE SOUND. THE LENS DISCOVERS A STRUCTURE. THE STRUCTURE CONTROLS THE SOUND.

A second rule is:

> WEIRDNESS NEEDS A FLOOR.

Do not flatten this project back into:
emotion -> mood -> genre -> instrument.

The point is to discover reusable causal operators.

## Epistemic rule

There is no scientifically unique soundtrack for any target. Use reliable research and conceptual models to identify plausible structure, but clearly separate:

- supported scientific/conceptual framing;
- inferred causal interpretation;
- procedural artistic transduction;
- speculative reusable mechanism.

Do not claim that a BPM, chord, scale, instrument, or production technique is scientifically "the sound" of a state.

## Required format for every target

For each target below, produce a complete standalone specimen using the same level of rigor and general format shown in the PDF.

Include:

1. **North-star sentence**
   - One compact line defining the target structurally.

2. **Conceptual model**
   - What interacting processes make the target recognizable?
   - Explicitly distinguish it from nearby specimens already in the PDF.

3. **2-4 genuinely different causal models**
   - These must differ mechanistically, not stylistically.
   - Select one for the primary sonification.
   - Preserve strong alternatives for alternate sonifications.

4. **Useful lenses**
   - Choose only lenses that earn their place.
   - Good candidates include predictive processing, attention, working memory, retrieval, learning, control theory, information theory, dynamical systems, interoception, reward, social signaling, network behavior, physiology, linguistics, psychoacoustics, ecology, failure behavior, maintenance cost, and phenomenology.
   - Invent another lens if it explains the target better.

5. **Relevant structural properties**
   - Examples: certainty, prediction error, information gain, salience, memory load, inhibition, approach/avoidance, monitoring, temporal distortion, coupling, settlement, recovery, threshold behavior, path dependence.

6. **Transduction map**
   Use:
   PROPERTY -> SONIC CONTROL VARIABLE -> MUSICAL CONSEQUENCE

7. **Full sonic specification**
   Use only fields that do causal work:
   - BASE BPM
   - ACTIVITY PULSE
   - METER
   - SUBDIVISION
   - GROOVE / MICROTIMING
   - RHYTHMIC DENSITY
   - EVENT ARRIVAL RATE
   - HARMONIC SYSTEM
   - MELODIC SYSTEM
   - PITCH BEHAVIOR
   - TIMBRE
   - INSTRUMENTATION BY FUNCTION
   - ARTICULATION
   - DYNAMICS
   - DYNAMIC RANGE
   - TEXTURAL DENSITY
   - REGISTER
   - SPECTRAL DENSITY / BRIGHTNESS
   - TRANSIENT CHARACTER
   - REPETITION RATE
   - PHRASE LENGTH
   - FORM
   - SECTION TRANSITION LOGIC
   - SILENCE / INTERRUPTION
   - STEREO / SPATIAL
   - DEPTH / REVERB
   - MASKING / CLARITY
   - DISTORTION / SIGNAL DEGRADATION
   - VOCAL BEHAVIOR
   - PRODUCTION

   Remember: KINETIC DENSITY IS NOT BPM.

8. **Temporal arc**
   - Model the target through time.
   - Do not bolt a generic song form on afterward.

9. **Invariant**
   - Identify the property that must remain recognizable while other dimensions mutate.
   - Explain what state the piece would become if the invariant were lost.

10. **5-12 explicit operators**
    - Write actual transformation rules, not adjectives.

11. **Instrument / sound palette by functional job**
    - No genre-costume shopping list.

12. **Final compact music-generator prompt**

13. **Anti-cliche test**
    - Name the obvious soundtrack costumes and reject them unless they perform a structural job.
    - The result should work even if the target word is never spoken.

14. **At least two alternate sonifications**
    - Use genuinely different causal models/lenses.
    - Do not give genre swaps.

15. **Mechanism harvest**
    After the musical design, forget the target and extract reusable machinery.

    For every harvested mechanism provide:
    - NAME
    - CAUSAL STRUCTURE
    - WHAT MUSIC CAN DO TO IMPLEMENT IT
    - CONTROL DIMENSIONS IT TOUCHES
    - HOW IT DIFFERS FROM SIMILAR EXISTING MECHANISMS
    - OTHER STATES / SYSTEMS IT COULD SONIFY
    - SOURCE TARGET
    - STATUS: NEW / VARIANT / DUPLICATE / COMPOUND

## Deduplication rule

Do not invent a new name merely because the new target used familiar machinery.

Compare every harvest against the mechanisms in the PDF.

Merge by **causal graph**, not wording.

Examples:
- a new kind of "withheld resolution" is not automatically new;
- a silence is not automatically the same mechanism if its causal role differs;
- microtiming is a control dimension, not a mechanism;
- predictive processing is a lens, not a mechanism.

If the causal structure is substantially the same, mark it VARIANT or DUPLICATE and explain why.

## Batch workflow

Process all 20 targets as separate full specimens.

After targets 5, 10, 15, and 20, perform a mini-audit:

- normalize synonyms;
- merge duplicates;
- identify crowded mechanism families;
- identify sparse mechanism-space;
- identify new control dimensions;
- identify useful compound mechanisms;
- check whether the next batch still maximizes conceptual distance.

Do not shorten later targets because the document is getting long. Keep rendering until the meat is gone off the bone.

If context or output limits become a problem, split the work into sequential files/runs and preserve a continuation ledger. Never silently compress unfinished targets into summaries.

## Deliverables

Produce:

1. one full specimen file per target;
2. **MECHANISM_DELTA.md** - only genuinely new or meaningfully revised mechanisms, with duplicate/variant notes;
3. **FAMILY_MAP_UPDATE.md** - new families, changed family boundaries, and cross-links;
4. **CONTRAST_PAIRS.md** - especially useful neighboring-state distinctions discovered during the batch;
5. **CONTROL_DIMENSIONS_DELTA.md** - any new musical knobs or useful state-dependent control relationships;
6. **NEXT_PROBES.md** - the next 10-20 targets selected specifically to fill remaining sparse regions, not because they are thematically similar;
7. **BATCH_SYNTHESIS.md** - what this twenty-target batch changed about the overall theory.

## The 20 targets

Process in this order unless evidence from the mini-audits gives a strong reason to reorder later items:

1. **Learning**
   - actual model update, error-driven adaptation, consolidation, decreasing prediction error.

2. **Unlearning**
   - old predictions weakening without necessarily being erased; extinction, persistence, context dependence.

3. **Relief**
   - predicted threat fails to arrive; unused preparation/control effort becomes unnecessary.

4. **Guilt**
   - an action violates a rule or harms another while the self remains repair-capable.

5. **Shame**
   - a specific error becomes evidence about the whole self-model. Explicitly contrast with guilt and embarrassment.

6. **Deja vu**
   - familiarity signal without successful source retrieval.

7. **Tip-of-the-tongue**
   - partial retrieval, neighborhood activation, phonological fragments, blocked access.

8. **Obsession**
   - salience resists extinction despite diminishing information gain.

9. **Procrastination**
   - activity without the relevant state transition; preparation mutates into avoidance.

10. **Flow state**
    - prediction, action, attention, and feedback become unusually well coupled. This is a positive/stable control specimen.

11. **A system becoming extremely good at solving the wrong problem**
    - proxy optimization; competence rises while relevance falls.

12. **An error-correction system protecting the error**
    - stabilizer machinery preserves the defect it should remove; pathological repair/homeostasis.

13. **Overfitting**
    - historical examples are modeled exquisitely while novel cases fail.

14. **Feedback delay**
    - corrective response arrives after conditions have changed; overshoot, oscillation, chasing obsolete state.

15. **Hysteresis**
    - identical current input produces different states because the route/history differs.

16. **Phase transition**
    - gradual quantitative change crosses a threshold and creates a qualitatively different regime.

17. **Emergence**
    - local rules create global structure no individual component contains or commands.

18. **Pluralistic ignorance**
    - private disagreement coexists with public conformity because agents incorrectly model what everyone else believes.

19. **Bureaucracy**
    - queues, permissions, duplicated state, handoffs, bottlenecks, responsibility diffusion, and processes spawning processes.

20. **Coordination failure**
    - agents want compatible outcomes but cannot align timing, information, role assignment, or action.

## What I especially want you to look for

Do not merely expand the number of emotion recipes.

Look for missing **operations**.

Examples of operations that may or may not already be sufficiently represented:

amplify; suppress; gate; delay; migrate; couple; decouple; entrain; desynchronize; recruit; abandon; habituate; sensitize; accumulate; diffuse; saturate; bifurcate; reset; reassign; invert; overwrite; conserve; leak; repair; misrepair; delegate; revoke; compress; expand; quantize; interpolate; extrapolate; classify; reclassify; stabilize; destabilize; overshoot; oscillate; lock; unlock; inherit; extinguish; generalize; overfit; underfit; synchronize; compete; cooperate; queue; bottleneck; deadlock; cascade; phase-change.

The purpose of the target is to expose machinery we have not named yet.

## Final instruction

The attached PDF is not a set of lyrics to imitate. It is the current map of a research system.

Extend the map.

Do not make music that illustrates the target word.

Build a musical system that behaves like the thing behaves, then strip the target away and keep whatever causal machinery survives.

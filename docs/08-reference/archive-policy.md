# Archive and Canonicalization Policy

## Preserve the mess; do not make the mess the manual

The repo’s historical documents are valuable because they preserve dead ends, accidents, naming history, prompt experiments, overclaims, jokes, speculative mechanisms, and the exact lineage of better ideas. They should not be deleted simply because later work became cleaner.

But preserving everything does not mean every statement deserves equal authority.

## Source layers

### `originals/`
Untouched intake copies. Evidence of what arrived.

### Legacy source folders
`art/`, `general/`, `suno_slop/`, and similar historical organization. Preserve until a later cleanup can prove all links and provenance survive.

### `ai_readable/`
Searchable transcriptions. These are source mirrors, not canonical synthesis.

### `docs/`
Current meaning, current organization, current caveats, and reusable procedures.

## What to do with incoming source documents

1. Archive the original.
2. Produce or verify a searchable transcription.
3. Audit the document for atomic information.
4. Route information by function, not source title.
5. Merge duplicate mechanisms.
6. Preserve genuinely conflicting interpretations and label them.
7. Put speculative ideas in backlog rather than deleting them.
8. Mark dangerous, disowned, or technically false rhetoric as archive-only when necessary.
9. Add provenance links.
10. Update the machine index.

## Do not silently rewrite history

If a later document corrects an earlier claim, canonical docs should state the correction while the earlier source remains intact. Examples already present in this project include:

- Temporary Minds moving away from false neural/embedding claims toward explicit procedural simulation.
- Semantic Manifold Game explicitly calling “latent-space navigation” a useful lie and defining the external analogue honestly.
- Technical roundtable participants challenging each other’s mechanism stories and demanding ablation.
- The user explicitly calling the extreme manifesto “kinda crazy” and “just for looks” while retaining the underlying aesthetic philosophy.

That evolution is useful data.

## Deprecation vocabulary

- **SUPERSEDED:** replaced by a stronger version.
- **MERGED:** absorbed into another mechanism.
- **DEMOTED:** still useful but no longer a standalone system.
- **FLAVOR ONLY:** aesthetic/persona material, not mechanism.
- **ARCHIVE ONLY:** preserved but not endorsed or operationalized.
- **OPEN HYPOTHESIS:** unresolved and testable.

Nothing has to vanish to stop being canonical.
